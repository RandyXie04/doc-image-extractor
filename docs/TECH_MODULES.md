# 核心模組技術規格與系統架構

本文件詳細記載書籍轉檔工具箱之四大核心模組技術細節、雙引擎調度、關鍵排版演算法與硬體加速架構。

---

## 一、四大核心模組規格

### 1. PDF 數學公式提取 (Formula Extractor)
- **核心模型**：YOLOv8 ONNX (`models/yolo_v8_ft.onnx`)。
- **推論框架**：ONNX Runtime，優先掛載 DirectML 執行提供者（相容所有 DirectX 12 GPU，包含 AMD、Intel、NVIDIA）；環境缺乏 GPU 時平滑降級為 CPU 推論。
- **邊界擴展機制**：提供使用者四向 Padding 微調滑桿，自動偵測上下標、分數線與積分界限，避免邊緣字元截斷。
- **批次處理**：PyMuPDF 頁面高解析度渲染（預設 200~300 DPI）與模型批次推論。

### 2. 雙引擎自適應 OCR 與圖文重排 (Dual-Engine OCR)
- **高速向量通道 (PyMuPDF)**：
  - 專用於原始數位向量 PDF，直接讀取底層字符編碼、幾何邊界與字型度量。
  - 毫秒級萃取速度，100% 杜絕 OCR 辨識錯字與形近字混淆。
- **深度辨識通道 (Surya OCR)**：
  - 專用於紙本掃描件、雙層 PDF 或已轉曲文字。
  - 包含文字偵測 (Text Detection)、文字識別 (Recognition)、版面區塊分割 (Layout Analysis) 與閱讀順序排序 (Reading Order)。
  - PyTorch CUDA 支援：偵測到 NVIDIA GPU 時自動配置 GPU 推論與動態批次量。
- **語意抽象與格式轉換**：
  - 統一匯流至中介 AST 結構，透過內建 Pandoc 轉為語意化 Word (`.docx`) 與標準 Markdown (`.md`)。

### 3. 文件圖片無損提取 (Image Extractor)
- **底層引擎**：PyMuPDF Stream Extractor。
- **特色**：
  - 自 PDF 內部物件流直接導出原始位元組資料，完全不經過二次壓縮或色彩空間轉換。
  - 支援 CMYK、RGB、Grayscale、Indexed 色彩空間與 ICC Profile 嵌入。
  - DOCX 格式直接解析 XML 封包中的 `word/media/` 資源。

### 4. 方正書版亂碼修復 (Founder Font Repair)
- **修復機制**：
  - 針對早期方正書版（BDC/Founder）、超星數位圖書館等非標準 CID 字型編碼。
  - 內建專用 CMap 與 Unicode 映射庫，逐字元計算字模外觀或字碼映射還原為標準繁/簡體 Unicode 字元。
  - 修復完成後直接封裝為標準 DOCX 交付排版。

## 二、關鍵架構與排版演算法

### 1. 無腳注模式雙通道架構 (No-Footnote Architecture)
- **問題背景**：傳統排版系統易將正文中的帶圈數字（①②③）、化學式括號或公式標號誤判為註腳引用，導致正文數字被錯誤剔除至頁底。
- **解決方案**：
  - 採用雙通道架構，業務管線入口預設開啟無腳注模式（`no_footnote=True`），徹底跳過所有註腳抽離判定，100% 維持內文連續流動。

### 2. 2D 座標三線表重建算子 (Three-Line Table Reconstructor)
- **強型別契約**：以 `@dataclass(frozen=True)` 定義 `TextSpan2D`、`TableRegion` 與 `ReconstructedTable`。
- **三線表識別**：基於頁面頂部大線條、表頭底部分隔線與表尾大線條的 2D 幾何投影，自動定位表格區域。
- **垂直居中單元格歸位**：解決跨列群組儲存格因 `y0` 居中而錯置至下排資料列的問題，自動上移歸位至首列。
- **表頭保護**：停用頂部硬編碼正則過濾，確保表頭單位符號（如 `ESR (mm/h)`）完整保留。

### 3. 首字下沉與標題段落智能修復
- **首字下沉識別**：偵測大型首字與後續段落的行距重疊，自動拼回正文開頭。
- **整數空白標題切分**：支援 `1 绪论`、`2.1 实验方法` 等標題正規化與黏連斷行切分。

## 三、硬體資源管理與隱私防護

- **動態硬體探測**：後端啟動時即時探測可用運算資源（CUDA GPU / DirectML / CPU 多核心），並在前端側邊欄顯示加速狀態。
- **零日誌生命週期管理**：
  - 伺服器預設不寫入永久磁碟日誌。
  - 所有使用者上傳檔、中繼預覽圖與產出壓縮檔均標記時間戳，超過 24 小時由背景 Janitor 自動安全銷毀。
  - 伺服器 In-Memory 狀態字典定時淘汰超時項目，防止記憶體洩漏。
